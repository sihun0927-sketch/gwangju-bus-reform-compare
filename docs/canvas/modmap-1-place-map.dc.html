places

Kakao 로컬 REST 대리 호출 → 상위 5개 → HTML. 검색 범위는 번들의 노선안 정류장 bbox + 5km. 같은 검색어는 Cache API에 하루

  • Kakao REST 키 (Worker 환경 변수 KAKAO_REST_KEY, ADR-0005)
  • 번들 JSON: 노선안 정류장 bbox
  • 외부: Kakao 로컬 API

개편 전 카드 / 개편 후 카드

용어

개편 전 카드개편 후 카드상태

카드 머리에 상태가 선다 — 직행 · 환승 1회 · 환승 2회 · 경로 없음. 판정 문장은 두지 않는다(§7 Q11). 두 카드의 안은 같은 모양이다

동적

GET /compare?
from=lat,lng&to=lat,lng

카드 한 쌍 + 경로 지도 자리를 한 조각으로. 카드 안에 그 경로의 좌표 JSON과 「다른 경로 더 보기」의 hx-get="/journey/…"

Worker

compare

안이 다섯이다 — network → candidates → search → rank → render. 노선망 둘 각각 한 번. 두 지점이 500m 이하면 「걸어갈 수 있는 거리」

요청당 CPU 중앙값 20~21ms — 무료 요금제 상한 10ms를 넘는다(§6-4 · §8)

  • 번들 JSON worker/data.json 2.02MB
  • stops 4,803 · routes 230 · route_stops 42,390
  • transfers 6,566 · route_links 7,250
  • D1은 쓰지 않는다 (ADR-0008)

「다른 경로 더 보기」로 펼치는, 노선 조합이 다른 경로 최대 2개. 카드마다 「지도에 표시」

GET /journey/{경로 키}

경로 하나의 정류장 목록 · 지표 · 좌표 배열 조각. 경로 키는 compare가 조각에 박아 둔 것이고, 저장소가 없어 링크만으로 열린다

Worker

journey

키를 풀어 번들에서 되살린다. 탐색을 다시 하지 않는다 — 구간마다 방향·순번만 고른다. 키가 번들과 안 맞으면 404와 한 줄 문구

  • 번들 JSON stops · route_stops (C와 같은 표)
  • 저장소 없음 — 키에 든 것이 전부다

Worker

geometry

경로 하나를 점 목록으로 편다 — 구간마다 승차부터 하차까지 지나는 정류장 전부와 두 지점. 길 양쪽이면 앞 점에 가까운 줄, 좌표 없는 줄은 건너뛴다. 도로 형상은 두지 않는다(직선)

그리는 map은 브라우저 코드이고 노선번호 탭과 같은 함수다

  • Kakao JS 키 (Cloudflare 환경 변수, ADR-0005)
  • 번들 JSON stops (좌표)
