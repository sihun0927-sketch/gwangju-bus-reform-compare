## 1. 한 문장

**정적 HTML 껍데기 + htmx 조각.** 페이지는 빌드 때 한 번 만들어 Cloudflare Pages에 올리고,
사용자가 무언가를 고를 때마다 htmx가 HTML 조각을 받아 그 자리에 끼운다. 조각은 두 종류다 —
노선번호 탭은 **빌드 때 만든 정적 파일**, 장소 탭은 **Worker가 D1을 읽어 만드는 동적 응답**.

계산은 빌드 스크립트(노선번호 탭)와 Worker(장소 탭)가 하고, 브라우저는 HTML만 받는다.

## 2. 부품과 역할

| 부품 | 무엇 | 이 프로젝트에서 하는 일 | 어디에 |
|---|---|---|---|
| **Cloudflare Pages** | 정적 파일 창고 | `out/` 전체를 냄. 껍데기, 노선 개편 목록 표, 노선번호 탭 조각 308개(카드 103 + 표 205), CSS, htmx, Kakao SDK 로더 | 배포 |
| **Cloudflare Worker** | 요청마다 실행되는 JS 서버 | 장소 탭 셋: `GET /places?q=`(Kakao REST 대리 호출) · `GET /compare?from=&to=`(경로 계산 → 카드 조각) · `GET /journey/{id}`(상세 조각 + 경로선 좌표) | 배포 |
| **Cloudflare D1** | SQLite DB | 정류장 좌표·노선망·비교표. Worker만 읽는다. 노선번호 탭은 쓰지 않는다 | 배포 |
| **빌드 스크립트** | 배포 전 한 번 도는 프로그램 | `data/source/`의 CSV 7개(시 공표 6 + `stops.csv`) → 정적 조각 파일 + D1 적재 SQL. 노선 변화 표 규칙 전부가 여기 | `tools/` |
| **htmx** | `hx-*` 속성 라이브러리 | 버튼·입력에 붙어 조각 URL을 받아 `hx-target`에 끼움. 페이지 새로고침 없음 | 브라우저 |
| **Kakao JS SDK** | 지도 | 지도 타일과 경로선·점을 **브라우저에서** 그림. htmx는 지도를 못 그린다. JS 키는 브라우저에 노출, 도메인 화이트리스트로 방어(ADR-0005) | 브라우저 |
| **Kakao REST API** | 장소 검색 | Worker가 대신 호출. REST 키는 Worker 환경 변수에만 둔다(ADR-0005) | Worker |

## 3. 두 탭의 정적 / 동적 분할

번호는 캔버스 아트보드의 번호와 같다. 회색 실선 = 정적, 초록 점선 = 동적.

### 3-1. 장소로 찾기 (캔버스 페이지 1)

| 번호 | 영역 | 정적/동적 | URL | 만드는 곳 |
|---|---|---|---|---|
| ① | 껍데기: 제목·탭·출발/도착 입력칸·안내 | 정적 | `index.html` | 빌드 |
| ④ | 자동완성 후보 (장소, 입력 중) | 동적 | `GET /places?q=전남대` → `<ul>` | Worker → Kakao REST |
| ⑤ | 판정 + 개편 전 카드 / 개편 후 카드 | 동적 | `GET /compare?from=lat,lng&to=lat,lng` | Worker → D1 → 경로 계산 |
| ⑥ | 다른 경로 카드 + 경로 지도 좌표 | 동적 | `GET /journey/{id}` | Worker. 선 긋기는 Kakao JS |

흐름: 껍데기 → 입력 → ④ → 선택 → ⑤ → 펼침 → ⑥. 예시 쌍 버튼은 두지 않는다(캔버스에서 삭제).

### 3-2. 노선번호로 찾기 (캔버스 페이지 2)

| 번호 | 영역 | 정적/동적 | URL | 만드는 곳 |
|---|---|---|---|---|
| ① | 껍데기: 노선번호 입력칸·안내 | 정적 | `index.html` | 빌드 |
| ② | 노선 개편 목록 표 111행 (개편 전 · 개편 후) | 정적 | `index.html` 안에 통째로 | 빌드 |
| ④ | 자동완성 후보 (번호, 최대 12) | 정적 조각 | `route-numbers/{앞글자}.html` 또는 브라우저 필터 — 미결 §8 | 빌드 |
| ⑤ | 표 필터 (tbody 교체) | 정적 조각 | 위와 같음 — 미결 §8 | 빌드 |
| ⑥ | 노선 변화 카드: 제목·대체 노선·방면 선택·대체 노선 선택·요약 칸 + 노선 지도 좌표 | **정적 조각** | `route/{번호}.html` | 빌드 (ADR-0002) |
| ⑦ | 노선 변화 표 | **정적 조각** | `route/{번호}/{개편 전 방면}/{대체 노선}/{개편 후 방면}.html` | 빌드 (ADR-0002, 0003, 0006) |

흐름: 입력 → ④/⑤ → 번호 확정 → ⑥ → 방면·대체 노선 고름 → ⑦. 조망 지도(버스가 오지 않는 정류장)는
두지 않는다(캔버스에서 삭제). **이 탭은 Worker·D1 없이 완전히 돈다.**

```
        ▼                                          ▼

   index.html        ← 껍데기 + 노선 개편 목록 표      정류장(좌표) · 노선망 · 비교표

   … (카드 103 · 표 205, ADR-0006)
        │
        ▼
 Cloudflare Pages ◄── htmx (노선번호 탭)
```

빌드 스크립트의 단계(노선 변화 표 부분, ADR-0003):

0. **번호 잇기** — 노선 표기를 (종류, 번호, 방면)으로 갈라 비교표와 노선안을 잇는다(ADR-0006). 못 찾는 쌍 0
1. **명칭 사전** — `명칭 변경 정류소.csv`에서 옛 이름 → 새 이름 집합. 옛 이름 하나에 새 이름 여럿 허용
2. **방면 분리** — 같은 종류+번호의 행을 방면으로 나눔. 개편 전 6개 번호 14행, 개편 후 지선97
3. **기·종점 정렬** — 개편 전 방면 × 대체 노선 × 개편 후 방면 쌍(205)마다 ① 기·종점 이름 → ② 정류장 겹침 → ③ `data/기종점정렬표.csv`
4. **기·종점 정류장 대조** — 상행끼리·하행끼리 최장 공통 부분열(LCS)로 정렬. 명칭 사전을 적용해 이름이 다른 같은 정류장을 「유지」로
5. **비고** — 명칭 변경 · 통폐합 · 이전 · 신설 (CSV 사실만. 상태는 적지 않는다)
6. **파일 쓰기** — `route/{번호}.html`, `route/{번호}/{개편 전 방면}/{대체 노선}/{개편 후 방면}.html`

## 5. 노선 변화 표 규격

캔버스 페이지 3에 문흥18 ↔ 간선18 실제 값으로 그려져 있다.

| 항목 | 규격 |
|---|---|
| 열 | `# · 개편 전 상행 정류장 · 개편 후 상행 정류장 · 개편 전 하행 정류장 · 개편 후 하행 정류장 · 비고` |
| 줄 | 정류장 이름을 순서대로 맞댄 것. 위에서 아래로 읽으면 버스가 가는 순서 |
| 색 | 개편 전에만 있는 줄 = `--worse-bg`(붉은 바탕), 개편 후에만 = `--better-bg`(초록 바탕). 글자 굵기는 같다 |
| 상태 | 유지 / 경유 제외 / 경유 추가. 주어는 노선 — 정류장이 없어진 것이 아니다. 화면에는 줄 색·범례·요약 칸에만 나온다 |
| 상행·하행 요약 칸 | 상행·하행 각각 유지/경유 제외/경유 추가 셋 = 여섯 칸, 같은 크기로 나란히. "상행 · 경유 제외 11곳" |
| 버튼 줄 | 개편 전 방면 선택(6개 노선만) / 대체 노선 선택 `[간선18] [지선10]` / 개편 후 방면 선택(대체 노선에 방면이 있을 때만) |
| 하행 없는 노선 | 하행 두 칸을 비우고 비고에 "순환 노선 · 하행 없음" 또는 "편도 운행 · 하행 없음". 열은 늘 여섯 |
| 방향 표시 | 기·종점 정렬에서 뒤집어 맞댄 경우, 표 아래에 "기점·종점이 반대라 뒤집어 맞댔습니다" 한 줄 |
| 제목 | 「<번호(방면)> 노선 변화」. 예: 「두암81(각화초교.장등동) 노선 변화」 |
| 출처 줄 | "출처: 광주광역시 시내버스 노선개편안 「노선개편 전·후 비교표」 · 「광주권역 개편전/개편후 노선안」" |

## 8. 미결

- **④⑤ 자동완성·표 필터의 출처.** 후보가 111개뿐이라 (a) 브라우저 안에서 `<tbody>`를 숨기는 작은 스크립트,
  (b) 앞글자별 정적 조각 파일 둘 다 가능. htmx만으로 갈지 정한다
- **장소 탭 Worker 설계 전부.** D1 스키마, 경로 계산(도보권 500m·환승 상한)을 Worker 안에서 할지,
  무료 요금제 CPU 시간 제한(요청당 10ms)에 들어가는지. 도보권 반경·환승 상한 같은 계산 규칙은
  이 리포에서 새로 정하고 **실측이 먼저**다. 별도 세션 크기
- **`절골입구`가 어느 쪽인가.** API의 `절골입구(북)`·`절골입구(서)`(약 40m) 중 `(북)`을 임의로 골랐다.
  노선 지도는 무해하지만 도보권·환승 계산은 달라진다. 장소 탭 설계 전에 다시 본다(ADR-0007)
- **신설 정류소 57개의 좌표.** `source/stops.csv`에 없다(신설 56 + `광주교대역2번출구`). 개편 후 BIS가 열리면
  다시 받고, 그때까지는 비워 둔다 — 지어낸 좌표를 넣지 않는다(ADR-0007)
- **`data/기종점정렬표.csv` 18행** 채우기. 열: 개편 전 번호 · 방면 · 대체 번호 · 개편 전 상행이 맞닿는 쪽(상행/하행)
