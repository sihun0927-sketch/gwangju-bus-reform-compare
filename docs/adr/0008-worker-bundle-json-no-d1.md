# 장소 탭의 데이터는 빌드가 미리 계산해 Worker 번들 JSON에 넣는다 — D1은 쓰지 않는다

2026-09-03 · 확정 (그릴링 Q1 · Q8 · Q9) · **ADR-0001의 「Worker + D1」 부분을 대체한다**

## 결정

1. **경로 계산에 필요한 구조는 빌드 스크립트가 만든다.** 노선안 CSV와 `stops.csv`에서 표 다섯을 계산해
   `worker/data.json` 하나로 쓴다. Worker는 요청 때 이 파일을 import해 조회·순위·HTML 렌더만 한다.

   | 표 | 열 | 뜻 |
   |---|---|---|
   | stops | STATION_NUM · ARS_ID · 이름 · lat · lng · 추정 여부 | `stops.csv` **줄 단위**. 길 양쪽이 따로 |
   | routes | 노선망(before/after) · 노선 이름 · 배차(비어 있음) | 개편 전 111 + 개편 후 119 |
   | route_stops | 노선 · 방향(상행/하행) · 순번 · 이름 · STATION_NUM | 노선안 이름 하나 → 그 이름의 줄 전부 |
   | transfers | STATION_NUM 쌍 · 거리(m) | 환승 도보 350m 안 정류장 쌍 |
   | route_links | 노선 쌍 · 환승 지점(STATION_NUM 쌍) · 거리 | 노선 쌍당 **최단 1개** |

2. **정류장의 정체성은 `stops.csv`의 줄이고 키는 STATION_NUM이다.** ARS_ID는 전남 정류장 147줄이 비어
   있어 키가 될 수 없다. 노선안은 이름만 주므로 이름 하나에 그 이름의 줄 전부(보통 길 양쪽 둘)를 그 노선의
   정류장으로 붙인다.

3. **D1은 만들지 않는다.** 표 다섯을 합쳐도 약 1MB로 Worker 무료 요금제 번들 상한(압축 3MB) 안이고, 데이터가
   시 공표 CSV 고정이라 요청 중에 바뀌지 않는다. 데이터가 바뀌면 빌드를 다시 돌려 배포한다.

4. 좌표 없는 정류장 57개는 같은 노선 앞뒤 정류장의 중점을 **추정 좌표**로 넣고 추정 여부를 표시한다.
   `stops.csv`에는 쓰지 않는다(ADR-0007 개정).

## 왜

장소 탭의 입력(좌표 쌍)은 무한이지만, 계산의 **재료**는 유한하고 고정이다. 노선 118개면 노선 쌍은 최대
7천이고, 환승 가능 정류장 쌍과 노선 쌍별 환승 지점은 빌드 때 한 번 계산하면 끝난다. 요청 때 남는 일은
도보권 정류장 찾기(좌표 거리 계산), 노선 집합 교집합, 노선 쌍 표를 두 번 잇는 것뿐이라 무료 요금제 CPU
10ms 안에 든다. ADR-0002가 노선번호 탭에 적용한 논리(고정 데이터는 빌드에서)를 그대로 잇는다.

D1을 두면 부품이 하나 늘고(스키마 · `wrangler d1 execute` · 로컬 D1), 요청마다 SQL 왕복이 생기며, 반경
판정을 SQL 범위 조건으로 흉내 내야 한다. 번들에 있으면 메모리 배열을 그대로 돈다. route_links를
「쌍당 최단 1개」로 줄이면 표가 작아 번들에 넣을 수 있다는 실측(다른 세션, 약 230KB)이 계기였고, 그 크기면
나머지 넷도 같은 자리에 두는 편이 부품이 적다.

## 기각

- **Worker가 요청마다 그래프 탐색.** 정류장 1,500개짜리 그래프를 매 요청 돌리면 CPU 제한이 걸릴 수 있고,
  같은 계산을 반복한다.
- **정류장×정류장 답을 전부 미리 계산.** 노선망당 약 225만 쌍이라 크고, 도보권 조합(출발 8 × 도착 8)까지
  담을 수 없다.
- **이름 단위 정류장.** 길 양쪽 중간점을 좌표로 쓰는 방식. 표는 작아지지만 노선 변화 표(이름 단위)와 경로
  계산(줄 단위)이 다른 단위를 쓰게 된다는 사용자 판단으로 기각. 양쪽 다 붙이면 도보 거리는 가까운 쪽으로 잰다.
- **route_links만 번들, 나머지는 D1.** 반경 판정이 SQL로 가고 부품은 그대로 둘이다. 절반만 옮길 이유가 없다.

## 따라오는 것

- 빌드 스크립트의 `seed` 모듈은 `bundle`로 이름이 바뀌고 출력은 `d1/seed.sql`이 아니라 `worker/data.json`.
- `wrangler.jsonc`에 `main`과 `run_worker_first`, 그리고 Worker가 나머지 주소를 정적 자산으로
  넘길 때 쓰는 `assets.binding`을 더한다. D1 바인딩은 없다.
- Worker 코드는 JavaScript(그릴링 Q6). 규칙 상수(도보권 500/1,000m · 환승 도보 350m · 정류장당 20초 ·
  도보 4km/h · 후보 8개)는 `worker/rules.js` 한 곳.
- 경로 키(`/journey/{id}`)는 구성 요소(노선망 · STATION_NUM · 노선 이름)를 base64url로 적은 것이라 번들만
  있으면 복원된다. 저장소가 없다.
- ADR-0001의 「Worker가 D1을 읽어 만든다」는 더는 맞지 않는다. 나머지(정적 껍데기 + htmx 조각, Kakao JS 지도)는
  그대로다.
- 첫 실측은 둘 — `worker/data.json`의 크기와 줄 수, `compare`의 요청당 CPU 시간.
