# 노선번호 탭의 조각은 빌드 때 정적 파일로 만든다

2026-09-02 · 확정 (그릴링 Q6)

## 결정

「노선번호로 찾기」의 결과 카드(⑥)와 노선 변화 표(⑦)는 요청마다 서버가 만들지 않는다.
빌드 스크립트가 CSV를 읽어 **HTML 파일로 미리 써 두고** Pages에 올리며, htmx는 그 파일을 받아 끼운다.

```
out/route/문흥18.html              ← 결과 카드: 번호 · 대체 노선 · 방면 선택·대체 노선 선택 버튼 [18][10]
out/route/문흥18/기본/18.html      ← 문흥18(방면 기본) ↔ 간선18 노선 변화 표
out/route/문흥18/기본/10.html      ← 문흥18 ↔ 지선10
out/route/두암81/각화초교.장등동/81.html   ← 방면이 여럿인 노선은 방면 디렉터리가 하나 더
```

노선 111개, 표 200개 안팎(비교표의 대체 쌍 187 + 방면 곱). 파일 하나 10KB 안팎.
Worker와 D1은 이 탭에 관여하지 않는다.

## 왜

입력이 유한하다. 이 탭이 답할 수 있는 질문은 「개편 전 번호 × 방면 × 대체 노선」 200개 안팎이
전부이고, 데이터(시 공표 CSV)는 고정이다. 요청마다 같은 답을 다시 계산할 이유가 없다.

정적 파일이면 Worker가 죽어도, D1이 비어 있어도 이 탭은 산다. 부품이 Pages 하나뿐이라 지킬 것도
하나다. CSV가 바뀌면 스크립트를 다시 돌려 배포한다.

## 기각

**Worker가 요청마다 D1을 읽어 만든다.** 장소 탭과 방식이 같아진다는 장점뿐이다. 대신 같은 규칙을
매 요청 다시 돌리고, 부품 둘(Worker 코드·D1 스키마)을 더 만들고 지켜야 하며, 무료 요금제 CPU 제한이
걸린다. 이 탭에는 요청 시점에만 정할 수 있는 값이 없다.

## 따라오는 것

- 노선 변화 표의 규칙(ADR-0003) 전부가 **빌드 스크립트**에 산다. Worker에는 없다.
- ④ 자동완성·⑤ 표 필터도 같은 논리로 정적 조각이거나 브라우저 안 필터다. 어느 쪽인지는 미결
  (`docs/architecture.md` §8).
- 캔버스 페이지 4 「Q6 조각 출처 a vs b」에 두 방식의 흐름이 나란히 그려져 있다.
