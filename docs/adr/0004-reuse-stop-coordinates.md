# 정류장 좌표는 이전 리포의 stops.json을 그대로 가져온다

2026-09-02 · **대체됨 — [ADR-0007](0007-stop-coordinates-from-bis-api.md)을 보라** (2026-09-03)

> 이 결정은 더 유효하지 않다. 좌표는 광주 BIS API에서 받아 `data/source/stops.csv`로 둔다.
> 아래 「기각」의 *공공 API로 새로 받는다* 항목이 근거로 든 「같은 원천이라 결과가 같다」가
> 사실이 아니었다 — 다른 원천이고 4,746개에 좌표 구멍이 없다. 「지어낸 좌표를 넣지 않는다」만 이어진다.

## 결정

시 공표 CSV 6개에는 정류장 좌표가 없다. 「장소로 찾기」는 좌표 없이 성립하지 않으므로, 이전 리포
[sihun0927-sketch/Hacker_AI](https://github.com/sihun0927-sketch/Hacker_AI)의 `data/stops.json` 4,312개를
이 리포 `data/stops.json`으로 옮겨 쓴다. 이 파일 하나만 가져온다. 신설 정류소 68개는
따로 채우고, 못 채운 것은 **비워 둔다**. 지어낸 좌표를 넣지 않는다.

## 그 좌표의 출처 (이전 리포에서 확인된 사실)

1. 개편 전 정류장 4,246개: 국토교통부 공공데이터 API(TAGO). 정류장 ID(`KJB…`)와 좌표
2. 개편 후 정류장: 개편안 PDF의 이름을 1번과 대조해 좌표를 물려받음. 1,504개 중 1,396개(92.8%)
3. 대조 안 된 신설 108개: Kakao 로컬 API 검색으로 59개, 이름만 바뀐 것을 옛 정류장에 합쳐 22개.
   남은 **27개는 좌표 없음** — 자치구와 이름뿐이라 검색이 0건인 곳

## 기각

- **공공 API로 새로 받는다.** 같은 원천이라 결과가 같고, 다시 만들면 몇 곳이 조금 움직여(이전 리포에서 겪음)
  검증을 처음부터 해야 한다.
- **장소 탭을 버린다.** 핵심 기능이다.

## 따라오는 것

- `data/stops.json`의 이름과 CSV의 정류장 이름을 잇는 규칙이 필요하다. 명칭 변경 사전(ADR-0003)이
  여기에도 쓰인다.
- D1의 정류장 표는 이 파일에서 적재한다. 노선번호 탭(ADR-0002)은 좌표를 쓰지 않는다.
