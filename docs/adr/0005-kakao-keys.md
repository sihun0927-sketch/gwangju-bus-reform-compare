# Kakao 키 둘: REST 키는 Worker에만, JS 키는 브라우저에 나가되 도메인으로 막는다

2026-09-02 · 확정

## 결정

Kakao 개발자 콘솔의 키 두 종류를 용도별로 다른 곳에 둔다.

| 키 | 쓰는 곳 | 어디에 두나 | 노출 |
|---|---|---|---|
| **REST API 키** | 장소 검색(지오코딩). `GET /places?q=` | Cloudflare **Worker 환경 변수**(`KAKAO_REST_KEY`) | 브라우저·리포에 절대 안 나감 |
| **JavaScript 키** | 지도 타일·경로선·점 그리기 | 빌드 때 정적 HTML에 박힘(`NEXT_PUBLIC_` 식 치환 또는 `<script>` 태그의 `appkey=`) | 브라우저에 그대로 보임. Kakao 콘솔의 **도메인 화이트리스트**(배포 주소만 등록)로 남이 못 쓰게 막는다 |

둘 다 리포에 커밋하지 않는다. REST 키는 Worker 대시보드(또는 `wrangler secret`)에, JS 키는 Pages
환경 변수에 넣고 빌드 때 치환한다. 두 키는 형식이 같아 헷갈리기 쉬우니 변수 이름에 `REST`/`JS`를 박는다.

## 왜

장소 검색은 Worker가 대신 호출하므로 REST 키를 서버에 숨길 수 있다. 숨길 수 있는 것은 숨긴다.

지도는 브라우저가 그린다(htmx는 지도를 못 그림, ADR-0001). 브라우저가 Kakao SDK를 부르는 이상
JS 키는 브라우저에 있어야 하고, 어떤 방법으로도 숨길 수 없다. 숨긴 척하지 않고 Kakao가 제공하는
도메인 제한으로 막는다.

## 기각

- **REST 키도 브라우저에서 직접 호출.** Worker가 있는데 서버 키를 노출할 이유가 없다.
- **JS 키를 Worker가 대신 받아 넘김.** 결국 브라우저에 도달하므로 노출은 같고 단계만 는다.

## 따라오는 것

- 로컬 개발: `.dev.vars`(Worker)와 `.env.local`(빌드)에 각각 두고 둘 다 `.gitignore`.
- 배포 주소가 바뀌면 Kakao 콘솔의 화이트리스트를 먼저 고친다. 안 고치면 지도만 안 뜨고 검색은 된다.
