# 노선 변화 표 — 열은 CSV를 따르고, 이름·방향·선택·비고 규칙은 이렇게 한다

2026-09-02 · 확정 (그릴링 Q3 · Q3' · Q4 · Q5 · Q7)

## 결정 1. 열 여섯 (사용자 지정)

`# · 개편 전 상행 정류장 · 개편 후 상행 정류장 · 개편 전 하행 정류장 · 개편 후 하행 정류장 · 비고`

노선안 CSV가 상행·하행을 따로 주므로 표도 따로 낸다.
줄은 정류장 이름을 순서대로 맞댄 것이라 위에서 아래로 읽으면 버스가 가는 순서다.

## 결정 2. 이름이 바뀐 정류장은 같은 정류장 (Q3 → a)

「명칭 변경 정류소」 102행으로 **옛 이름 → 새 이름 집합** 사전을 만들어 맞대기 전에 적용한다.
옛 이름 하나가 새 이름 여럿으로 갈라지는 경우(법원입구 → 광주법원검찰역1번출구 / 2번출구)와
여럿이 하나로 합쳐지는 경우(송암공단입구 ID 3개 → 송암산단입구)를 모두 허용한다. 노선 CSV에
정류장 ID가 없어 이름이 유일한 키이기 때문이다.

같은 정류장이면 한 줄 「유지」로 두고 비고에 "명칭 변경: 문흥고가 → 문화육교"를 적는다.

기각: 다른 정류장으로 보고 두 줄(경유 제외 + 새로)로 둔다. 자리는 그대로인데 「경유 제외」이 늘어
개편을 실제보다 나쁘게 보여 준다.

「경유 제외」의 화면 문구 규칙("이 버스가 안 옵니다", 다른 노선은 올 수 있음)은 구현 때 `CONTEXT.md`에서
확정한다(사용자 결정).

## 결정 3. 기·종점 정렬는 세 단계 (Q3' → d)

개편 후 노선의 기·종점이 개편 전과 반대인 쌍이 있다(문흥18 장등동→진곡산단 vs 간선18 하남고등학교→장등동).
상행끼리 그대로 맞대면 순서가 거꾸로라 전부 「경유 제외 / 경유 추가」가 된다. 그래서:

1. **기·종점 이름**이 같거나 서로 바뀌어 있으면 그것으로 정한다 — 187쌍 중 87
2. 아니면 **정류장 목록이 더 많이 겹치는 쪽**(상행↔상행+하행↔하행 vs 상행↔하행+하행↔상행의 LCS 합)을
   고른다. 차이가 뚜렷할 때만 — 73쌍
3. 그래도 애매한 쌍(겹침이 적거나 두 방향 차이가 작음)은 `data/기종점정렬표.csv`에 **사람이 적는다** — 16쌍 (2026-09-03 개정 2: 18쌍)

실측은 `tools/measure_direction.py`. 기각한 (a) "1단계만 자동, 나머지 89쌍은 사람이 적음"은
사람 손이 다섯 배 더 간다. 뒤집어 맞댄 쌍은 표 아래에 그 사실을 한 줄로 밝힌다.

## 결정 4. 대체 노선이 여럿이면 대체 노선 선택 (Q4 → a)

번호만 적은 버튼 한 줄 `[18] [10]`. 하나를 누르면 그 노선과 맞댄 표 하나가 나온다. 개편 전 방면이
여럿인 5개 노선은 방면 버튼 한 줄이 위에 더 붙는다. (2026-09-03 개정 2: 6개 노선, 버튼 줄 셋, 노선 이름 표기)

기각: 열 늘림(첨단94는 대체가 여덟이라 14열이 되어 못 읽음), 표 여러 개 세로 쌓기(너무 길다).
대체 노선 하나만 보이면 다른 대체 노선이 덮는 정류장이 「경유 제외」로 보인다. (2026-09-03 개정: 비고로 보완하지 않는다 — 아래 개정 절)

## 결정 5. 비고는 넷 다 (Q5)

해당하는 것을 " · "로 이어 적는다.

| 조건 | 비고 | 출처 |
|---|---|---|
| 이름이 바뀐 같은 정류장 | 명칭 변경: 옛 이름 → 새 이름 | 명칭 변경 정류소.csv |
| 개편 후에만 있고 신설 목록에 있음 | 신설 정류소 | 신설 정류소.csv |
| 개편 전에만 있고 통폐합 목록에 있음 | 구분(폐지/통폐합/이전) · 사유 | 통폐합이전정류소.csv |
| 개편 전에만 있는데 고르지 않은 다른 대체 노선이 섬 | 대신 서는 대체 노선: 10 | 비교표 + 개편후 노선안 |

## 결정 6. 하행이 없는 노선은 열을 유지 (Q7 → a)

순환 노선(개편 전 7행, 개편 후 1행)은 하행 두 칸을 비우고 비고에 "순환 노선 · 하행 없음".
기각: 3열로 줄임(표 읽는 법이 노선마다 달라짐), 상행을 뒤집어 하행에 채움(데이터에 없는 값을 지어냄).

## 2026-09-03 개정 (화면 용어 확정, CONTEXT.md 「노선번호로 찾기」)

- 표 이름은 **노선 변화 표**, 화면 제목 「<번호(방면)> 노선 변화」. 카드는 **노선 변화 카드**.
- 상태 이름은 **유지 · 경유 제외 · 경유 추가**. 팀원들이 「안 옴 / 새로」를 폐지·신설로 읽어서 바꿨다.
  주어는 노선이다 — 정류장이 없어진 것이 아니다.
- **결정 5(비고) 축소.** 비고는 CSV 사실 넷(명칭 변경 · 통폐합 · 이전 · 신설)만 적고, 상태 문구와
  「대신 서는 대체 노선」은 적지 않는다. 상태는 줄 색·범례·상행·하행 요약 칸이 말한다. 대가: 고르지 않은
  다른 대체 노선이 서는 정류장은 경유 제외로만 보이고, 사용자가 그 노선 버튼을 눌러야 안다.
- 방향 규칙 이름은 **기·종점 정렬**(파일 `data/기종점정렬표.csv`), 줄 규칙 이름은 **기·종점 정류장 대조**.
- 버튼은 **방면 선택 / 대체 노선 선택** 두 줄로 따로 부른다.

## 2026-09-03 개정 2 (노선 이름과 방면, ADR-0006)

- **결정 3 실측 갱신.** 쌍을 「개편 전 방면 × 대체 노선 × 개편 후 방면」으로 세면 205쌍 — ① 92 · ② 95 ·
  ③ 사람이 적음 18(겹침 약함 16 + 동률 2). 옛 수치(187쌍, 87·73·16)는 번호만 견주던 때 것이라 급행03·05·06이
  간선에 붙어 있었다.
- **결정 4 버튼 표기.** 번호만 `[18] [10]`이 아니라 노선 이름 `[간선18] [지선10]`. 03·05·06은 급행과 간선이
  따로 있어 번호만으로는 구별이 안 된다. 버튼 줄은 셋 — **개편 전 방면 선택**(6개 노선) / **대체 노선 선택** /
  **개편 후 방면 선택**(대체 노선에 방면이 있을 때만, 지선97).
- **결정 6 편도.** 하행 없는 노선이 순환만이 아니다. 지선97(빛그린산단출근)은 편도라 비고는
  "편도 운행 · 하행 없음". 칸 비우는 방식은 같다.
- 조각 경로는 `route/{번호}/{개편 전 방면}/{대체 노선}/{개편 후 방면}.html`.
