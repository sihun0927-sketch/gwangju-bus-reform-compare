# 정류장 변화 표 v2 — 열은 CSV를 따르고, 이름·방향·갈래·비고 규칙은 이렇게 한다

2026-09-02 · 확정 (그릴링 Q3 · Q3' · Q4 · Q5 · Q7)

## 결정 1. 열 여섯 (사용자 지정)

`# · 개편 전 상행 정류장 · 개편 후 상행 정류장 · 개편 전 하행 정류장 · 개편 후 하행 정류장 · 비고`

노선안 CSV가 상행·하행을 따로 주므로 표도 따로 낸다. 목업 v1(개편 전 · 개편 후 · 변화 3열)은 폐기.
줄은 정류장 이름을 순서대로 맞댄 것이라 위에서 아래로 읽으면 버스가 가는 순서다.

## 결정 2. 이름이 바뀐 정류장은 같은 정류장 (Q3 → a)

「명칭 변경 정류소」 102행으로 **옛 이름 → 새 이름 집합** 사전을 만들어 맞대기 전에 적용한다.
옛 이름 하나가 새 이름 여럿으로 갈라지는 경우(법원입구 → 광주법원검찰역1번출구 / 2번출구)와
여럿이 하나로 합쳐지는 경우(송암공단입구 ID 3개 → 송암산단입구)를 모두 허용한다. 노선 CSV에
정류장 ID가 없어 이름이 유일한 키이기 때문이다.

같은 정류장이면 한 줄 「그대로」로 두고 비고에 "명칭 변경: 문흥고가 → 문화육교"를 적는다.

기각: 다른 정류장으로 보고 두 줄(안 옴 + 새로)로 둔다. 자리는 그대로인데 「안 옴」이 늘어
개편을 실제보다 나쁘게 보여 준다.

「안 옴」의 화면 문구 규칙("이 버스가 안 옵니다", 다른 노선은 올 수 있음)은 목업 규칙을 따르되
구현 때 `CONTEXT.md`에서 확정한다(사용자 결정).

## 결정 3. 방향 맞대기는 세 단계 (Q3' → d)

개편 후 노선의 기·종점이 개편 전과 반대인 쌍이 있다(문흥18 장등동→진곡산단 vs 간선18 하남고등학교→장등동).
상행끼리 그대로 맞대면 순서가 거꾸로라 전부 「안 옴 / 새로」가 된다. 그래서:

1. **기·종점 이름**이 같거나 서로 바뀌어 있으면 그것으로 정한다 — 187쌍 중 87
2. 아니면 **정류장 목록이 더 많이 겹치는 쪽**(상행↔상행+하행↔하행 vs 상행↔하행+하행↔상행의 LCS 합)을
   고른다. 차이가 뚜렷할 때만 — 73쌍
3. 그래도 애매한 쌍(겹침이 적거나 두 방향 차이가 작음)은 `data/방향표.csv`에 **사람이 적는다** — 16쌍

실측은 `tools/measure_direction.py`. 기각한 (a) "1단계만 자동, 나머지 89쌍은 사람이 적음"은
사람 손이 다섯 배 더 간다. 뒤집어 맞댄 쌍은 표 아래에 그 사실을 한 줄로 밝힌다.

## 결정 4. 대체 노선이 여럿이면 갈래 선택 (Q4 → a)

번호만 적은 버튼 한 줄 `[18] [10]`. 하나를 누르면 그 노선과 맞댄 표 하나가 나온다. 개편 전 방면이
여럿인 5개 노선은 방면 버튼 한 줄이 위에 더 붙는다.

기각: 열 늘림(첨단94는 대체가 여덟이라 14열이 되어 못 읽음), 표 여러 개 세로 쌓기(너무 길다).
갈래 하나만 보이면 다른 대체 노선이 덮는 정류장이 「안 옴」으로 보이므로 비고의 「대신 서는 대체 노선」이 보완한다.

## 결정 5. 비고는 넷 다 (Q5)

해당하는 것을 " · "로 이어 적는다.

| 조건 | 비고 | 출처 |
|---|---|---|
| 이름이 바뀐 같은 정류장 | 명칭 변경: 옛 이름 → 새 이름 | 명칭 변경 정류소.csv |
| 개편 후에만 있고 신설 목록에 있음 | 신설 정류소 | 신설 정류소.csv |
| 개편 전에만 있고 통폐합 목록에 있음 | 구분(폐지/통폐합/이전) · 사유 | 통폐합이전정류소.csv |
| 개편 전에만 있는데 고르지 않은 다른 대체 노선이 섬 | 대신 서는 대체 노선: 10 | 비교표 + 개편후 노선안 |

## 결정 6. 하행이 없는 노선은 열을 유지 (Q7 → a)

순환 노선(개편 전 7행, 개편 후 1행)은 하행 두 칸을 비우고 비고에 "순환 노선 · 하행 없음".
기각: 3열로 줄임(표 읽는 법이 노선마다 달라짐), 상행을 뒤집어 하행에 채움(데이터에 없는 값을 지어냄).
