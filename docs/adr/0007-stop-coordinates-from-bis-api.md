# 정류장 좌표는 광주 BIS API에서 받아 `data/source/stops.csv`로 둔다

2026-09-03 · 확정 · **ADR-0004를 대체한다**

## 결정

정류장 좌표의 출처를 이전 리포의 `stops.json`에서 **광주 BIS 공개 API**로 바꾼다.
구현에서 좌표가 필요한 곳은 모두 `data/source/stops.csv`를 읽는다. `data/stops.json`은 만들지 않는다.

| 파일 | 무엇 | 만드는 것 |
|---|---|---|
| `data/back_up/api_stops.json` | API 응답 원본. 고치지 않는다 | `tools/fetch_stops.py` |
| `data/source/stops.csv` | 정류장 4,746개 × 8열. **좌표의 유일한 출처** | `tools/build_stops.py` |
| `data/name_canon.json` | 노선안 표기 → API 정식 표기 8개 | `tools/build_stops.py` |

엔드포인트는 `http://api.gwangju.go.kr/json/stationInfo`. 키는 `.env`의 `GWANGJU_BUS_KEY`이며
커밋하지 않는다(ADR-0005). 연 단위로 갱신되는 자료라 빌드 때 부르지 않는다 — 사람이 받아 커밋한다.

`stops.csv`는 빌드 스크립트가 읽는 입력이라 `source/`에 둔다 — 시 공표 CSV 6개와 같은 자리다.
`source/`의 파일 중 스크립트가 쓰는 것은 이 하나뿐이며, 원본은 `back_up/api_stops.json`이다.

열은 API 응답 그대로다.

```
STATION_NUM, BUSSTOP_NAME, ARS_ID, NEXT_BUSSTOP, BUSSTOP_ID, LONGITUDE, NAME_E, LATITUDE
```

## 왜 바꾸나 (측정한 것)

| | ADR-0004 (`stops.json`) | 이 결정 (`stops.csv`) |
|---|---|---|
| 정류장 수 | 4,312 | **4,746** |
| 좌표 없음 | 27 | **0** |
| 정류장 ID | `KJB…`, 리포에서 안 쓰임 | `ARS_ID` — 명칭 변경 CSV의 ID와 **102/102** |
| 출처 | 국토부 TAGO 경유 | 광주 BIS 직접 |
| 개편 전 노선안 정류장 1,499개 | 미측정 | **1,499 (100%)** |
| 개편 후 노선안 정류장 1,507개 | 미측정 | 1,369 (90.8%) |

ADR-0004가 API 재취득을 기각한 근거는 「같은 원천이라 결과가 같다」였다. 실제로는 다른 원천이고,
좌표 구멍 27개가 0이 되며, CSV의 4자리 ID와 곧바로 이어지는 열이 따라온다. 근거가 사실이 아니었다.

개편 후에서 못 찾은 **138개**는 전부 정체가 밝혀졌다 — 명칭 변경 새 이름 81 · 신설 56 ·
`광주교대역2번출구` 1(2호선 신설). 개편으로 생기거나 이름이 바뀌는 정류장이라 개편 전 API에 없는 것이 맞다.

## 이름을 잇는 규칙 둘

1. **공백을 붙인다.** 노선안 표기를 API 정식 표기로 바꾼다. 무시하지 않고 **하나로 정한다** —
   `stops` 표의 이름과 `route_stops`의 이름이 같은 문자열이라야 D1에서 그냥 조인된다.
   `덕남마을입구 → 덕남마을 입구`, `수완중흥S-클래스2차`, `진곡동길`, `하남산단5번로교차로` 넷.
2. **규칙으로 안 되는 넷은 예외로 적는다.** `압촌마을종점 → 압촌마을`(종점 접미),
   `절골입구 → 절골입구(북)`(**표기 차이가 아니다** — 아래를 보라),
   `살레시오살레시오고/교통문화연수원 → 살레시오고/교통문화연수원`(노선안 오타),
   `광주교대역2번출구 → null`(API에 없다).

`null`은 **좌표 없음**이라는 뜻이다. 지어낸 좌표를 넣지 않는다 — ADR-0004에서 이어받는 규칙이다.
**예외 하나(2026-09-03 개정)**: 장소 탭의 경로 계산에서만 좌표 없는 57개에 같은 노선 앞뒤 정류장의 중점을
「추정 좌표」로 붙인다. `stops.csv`에는 쓰지 않고 번들 JSON에 추정 여부 플래그와 함께 들어가며, 화면에는
「추정 위치」로 표시한다(ADR-0008).

## API 자료의 함정

- **이름 46개에 꼬리 공백이 있다.** `'대산         '`처럼. `'대산'`과 둘 다 있어서 공백을 무시하면
  4쌍이 뭉친다. 적재할 때 `BUSSTOP_NAME.strip()`을 걸고, 대표는 **짧은 쪽**으로 고른다.
- **`ARS_ID`가 1,697개 비어 있다.** 광주 밖(전남 통합분)으로 보인다. ID 조인은 광주 정류장에만 된다.
  명칭 변경 102행은 모두 광주라 영향이 없다.
- `NEXT_BUSSTOP` 528개, `NAME_E` 188개가 비어 있다. **`LATITUDE`·`LONGITUDE`는 4,746개 전부 있다.**

## 기각

- **이전 리포 `stops.json`을 그대로 쓴다(ADR-0004).** 좁고(4,312) 구멍이 있고(27) ID가 없다.
- **`stops.json` 형식을 유지한다.** 사람이 열어 보는 자료다. 열 이름이 API와 같은 CSV가 대조하기 쉽다.
- **신설 56개를 Kakao 검색으로 채운다.** 이번 범위 밖. 비워 두는 것이 지어내는 것보다 낫다.
- **빌드 때 API를 부른다.** 연 단위 자료다. 호출 실패가 빌드 실패가 될 이유가 없다.

## 따라오는 것

- 구현에서 좌표를 읽는 곳은 `data/source/stops.csv` 하나다. `route_geometry`와 `bundle`이 여기서 읽는다.
- 정류장 이름을 대조하기 전에 `name_canon.json`을 통과시킨다.
- 좌표 없는 정류장(신설 56 + 신규 1)은 `route_geometry`에서 건너뛰고 앞뒤를 잇는다(ADR-0004에서 이어받음).
- **ADR-0003의 전제 「정류장 ID가 없어 이름이 유일한 키」가 더는 맞지 않는다.** 명칭 변경 102행은
  `ARS_ID`로 직접 이을 수 있다. 명칭 사전을 단순하게 만들 여지가 있다 — 별건으로 다시 본다.
- **`절골입구`는 표기를 맞춘 것이 아니라 고른 것이다.** API에는 `절골입구(북)`(ARS 2333·2334)과
  `절골입구(서)`(ARS 2147·2148)가 서로 다른 정류장으로 있는데 노선안에는 이름이 하나뿐이라 `(북)`을
  임의로 골랐다. 두 지점이 약 40m라 `route_geometry`가 선을 그리는 데도, 장소 탭의 도보권 500m·환승 도보
  350m 판정에도 영향이 없다(2026-09-03 확인). `(북)`으로 둔다.
- 신설 정류소 좌표를 채우는 일은 남아 있다. 개편 후 BIS가 열리면 그때 다시 받는다.
